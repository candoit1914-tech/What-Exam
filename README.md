# What Exam — WhatsApp Examination System

Exams with **automatic marking scheme generation** delivered over WhatsApp.

Every exam automatically gets a complete, editable marking scheme — whether the
questions are typed by hand, extracted from a PDF, or generated by AI.

## Features

- **Create exams 3 ways**: manually, by uploading a PDF, or by AI generation.
- **Automatic marking schemes**: objective answers stored on creation; theory
  questions get an AI-generated model answer, key points, scoring rubric,
  presentation & grammar marks. Everything is editable before publishing.
- **PDF upload**: text is extracted, **every** question is parsed — objective
  and theory alike, in paper order — answer keys are detected, any missing
  answers are generated by AI, and an import that comes back clearly shorter
  than the paper warns the admin instead of failing quietly.
- **Only this app's instructions go to the student**: a paper's own printed
  instructions ("Answer all questions in this section", "Read the following
  passage…") are dropped, so WhatsApp carries the instructions the app writes
  — the intro block, "Reply with the letter of your answer", the option line —
  plus the paper's headings, passages and questions. Reading passages still
  arrive, because a question cannot be answered without them.
- **Send starts the exam**: pressing Send pushes the instructions and question
  1 straight away (figures above the question, as always) — there is no
  "Reply *START*" waiting room. The clock is armed by the student's first
  reply, so paper sitting unread costs nobody time. If WhatsApp refuses the
  free-form message (a number that has not messaged in 24 hours, where only an
  approved template may go out), the invite behind it is the fallback: the
  student's first reply opens the paper exactly as before, and a paid paper
  still starts with its checkout link.
- **Diagrams in PDFs**: figures are extracted (a question that carries more
  than one keeps all of them) and printed **above the question they belong to**
  on every surface — WhatsApp, the dashboard, and the student report — so the
  diagram is read before the question that asks about it. A paid paper whose
  first question opens inside an approved template still gets its figure: it is
  recorded as owed and delivered on the student's first reply, which is what
  opens the service window. Vector diagrams are assembled from the paths they
  are drawn with and cropped **with their labels and colours**. When a page's
  own text says "study the diagram above" but the page scan found nothing,
  AshnaAI's vision is asked to point at the printed figure — it never draws
  one, it only boxes what is already there, and a box over blank paper is
  discarded.
  - The import note reports what was **attached** — files that really exist —
    and names the reason when one could not be rendered, instead of promising
    figures the student will never see.
  - Every figure send is **recorded and retried**: a bubble the gateway refuses
    is owed, not lost, and goes out on the student's next message. The reason
    stays in `message_outbox`, so `npm run figures` shows it.
  - Two transports: the bytes go to WhatsApp's Media API first; if Meta will
    not take them, the same picture is sent as a **signed link**
    (`/figure/:file?token=…`, one file, one expiry) for WhatsApp to fetch.
  - `npm run figures` answers "why did the student get no picture?" on its own —
    per exam it reports figures attached, files missing from disk, and every
    figure delivery that has not succeeded, with its error.
- **AI generation**: produces correct answers, explanations, difficulty level,
  and learning objectives for every question. The count is exact: ask for
  40 objective and 5 theory and that is what you get — never 43 and 2,
  never 37 and 5. A provider that cannot deliver the full count fails
  loudly instead of saving a short paper.
- **Answer any N of M**: papers that ask the student to choose are honoured.
  Rules are read from the uploaded PDF ("Answer any FOUR questions from
  Section B", "Questions 1 and 2 are compulsory"), editable in the dashboard,
  and the student picks their questions by tapping in WhatsApp. Compulsory
  questions are never offered as a choice.
- **WhatsApp delivery** (official WhatsApp Cloud API): students reply in chat,
  the backend sends the next question after each answer, and the timer runs
  until the exam ends.
- **Instant objective marking** and **AI theory marking** (correctness,
  completeness, accuracy, relevance, keywords, logical explanation).
- **Photo answers (theory)**: students can send a written/drawn answer as a
  WhatsApp photo. With `AI_VISION=true` the AI grades the image; otherwise the
  answer is flagged for manual review. Photos appear in the dashboard and the
  student report.
- **Results**: score, percentage, pass/fail, downloadable web report, answer key,
  AI feedback, all saved to the dashboard. Admins can review and adjust theory
  marks before finalizing.
- **Free or paid papers**: when creating an exam the admin picks *Free* (the
  default, unchanged) or *Paid* with an amount in GHS. A paid paper sends a
  Paystack checkout link on WhatsApp next to the invite and stays shut — no
  question, no countdown, no session — until Paystack confirms the charge, then
  opens by itself.

## Requirements

- Node.js 22.5+ (Node 24 works great on Termux) — uses the built-in `node:sqlite`, so no native compilation is needed
- A WhatsApp Business account + Meta app (for the official Cloud API)
- Any OpenAI-compatible AI endpoint (OpenAI, Groq, OpenRouter, Ollama, ...)

## Setup

```bash
cd La_Exam
npm install
cp .env.example .env
# edit .env — set WHATSAPP_* and AI_* values
npm run config:check  # verify your .env before booting
npm run start:all     # runs backend (:3000) + frontend (:8080)
```

Or run them separately:

```bash
npm run start:backend    # API + webhook + reports on :3000
npm run start:frontend   # admin dashboard on :8080
```

Run the test suite with:

```bash
npm test
```

**About linting:** this repo has **no linter and no typechecker**. `package.json`
defines no `lint`, `format` or `typecheck` script, and there is no ESLint or
Prettier config at the root (the only ESLint entries live in
`advert/package-lock.json`, which belongs to a separate project). The test suite
is therefore the *only* automated gate: `npm test` is what a change is checked
against, and any report should say "there is no linter to run" rather than
claiming a lint passed. Style is the surrounding file's own style — comments
explain why the code is shaped this way, names say what they mean.

> **Android/Termux note**: if the project lives on external storage
> (`/storage/emulated/0/...`, a FUSE filesystem), install with
> `npm install --no-bin-links` (sdcard cannot create symlinks). Everything runs
> from plain JS + the built-in SQLite module, so no native builds are required.

The admin dashboard is then at http://localhost:8080 (or http://<your-termux-ip>:8080),
talking to the backend API at http://localhost:3000.

## WhatsApp Cloud API setup

1. Create an app at https://developers.facebook.com and add the *WhatsApp* product.
2. Note the **Phone Number ID** and generate a **Token** (API Setup page).
3. Create a webhook and subscribe to the `messages` field. The callback URL is:

   ```
   https://your-app.example.com/webhook/whatsapp
   ```

   Use the **Verify Token** you set in `.env`.

4. Set `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, and
   `WHATSAPP_VERIFY_TOKEN` in `.env`.
5. Optional: set `AI_VISION=true` in `.env` only when `AI_MODEL` accepts image
   input (e.g. `gpt-4o`, `gpt-5-mini`). Photo answers are then AI-graded with a
   manual-review fallback; without it they are always flagged for review. It also
   lets a PDF import ask the model to point at a figure the page scan could not
   assemble on a page whose text refers to one — the model only boxes what is
   already printed, it never draws a figure.

> Exposing the server publicly requires a tunnel (ngrok, cloudflared) or a
> VPS. The official API needs a public HTTPS URL.

## Exam workflow

1. **Create an exam** — manually, from a PDF, or with AI. The marking scheme is
   generated automatically as questions are added.
2. **Publish** the exam (locks editing).
3. Add **recipient phone numbers** on the Recipients tab.
4. Click **Send Exam to Recipients** — the first question is delivered by
   WhatsApp.
5. Students reply with letters (objective) or full text (theory). The backend
   marks instantly and sends the next question.
6. On a paper that says "answer any N", the student is offered a WhatsApp list of
   the optional questions for that section instead of being sent one
   automatically. They tap to toggle (or type the numbers and `CONFIRM`), and
   only the questions they picked are delivered. `CHANGE` reopens the list.
   Compulsory questions are sent without asking. Set or correct the rules on the
   exam's Selection Rules card.
7. The exam timer runs from session start; when time is up the exam is finalized
   automatically.
8. If the server restarts mid-exam, any session past its deadline is finalized
   automatically on boot — the student still receives the report and
   certificate for the answers given so far.
9. Results appear on the dashboard with a printable web report at
   `/report/<sessionId>`. Theory answers flagged for review can be adjusted
   manually. Grading is against the priced paper (`paper_total`), so a student
   who chose 2 of 3 is marked out of the sum of the 2 they answered.

### Starting without the "Send" button

If the student messages the bot first (before you send them anything), and they
are a recipient of exactly one published/live exam, the exam starts
automatically.

## Paid exams (Paystack)

Free exams are untouched by any of this — nothing below is needed until an admin
actually prices a paper.

1. Add your keys to `.env` (see the *Paystack* block in `.env.example`):
   `PAYSTACK_SECRET_KEY` (and `PAYSTACK_PUBLIC_KEY` if you show it anywhere).
   Ghana accounts settle in **GHS**; the price is sent to Paystack in pesewas.
2. When creating (or editing) an exam, set **Exam type → Paid** and enter the
   price in GHS. A paid exam with no amount is refused rather than sold free.
3. **Send** as usual. Each recipient gets the normal invite followed by their own
   checkout link. Sending a paid exam with no secret key is refused up front, so
   nobody receives a dead link.
4. Register the webhook so payments open papers instantly — dashboard.paystack.co
   → Settings → Webhooks:

   ```
   https://your-app.example.com/webhook/paystack
   ```

   It is verified with `x-paystack-signature` (HMAC-SHA512 of the raw body) and
   is mounted before `express.json()`, exactly like the WhatsApp webhook.
5. A student who pays gets a confirmation and their paper opens without another
   reply. If the webhook never arrives (local dev, no public URL), the pending
   reference is verified against the Paystack API on the student's next message,
   and a background sweep (every minute) settles any checkout that went missing
   and re-opens any paid paper with no attempt — so a lost webhook costs a
   student at most one sweep interval, never a reply. Either way the paper only
   opens for a charge whose amount and currency match what was asked.

The exam's **Payments** tab lists every checkout: pending, paid, channel,
reference and the total collected.

For recipients who have not messaged the WhatsApp number in the last 24 hours,
Meta only allows approved templates. To deliver a paid link before the student
replies, configure `WHATSAPP_PAYMENT_TEMPLATE_NAME` with an approved Utility
template whose body variables are `{{1}}` exam title, `{{2}}` price, and `{{3}}`
the full Paystack checkout URL. To send the first question immediately after
the payment webhook, also configure `WHATSAPP_PAID_START_TEMPLATE_NAME` with an
approved Utility template whose body variables are `{{1}}` exam title, `{{2}}`
the first question and its options, and `{{3}}` duration in minutes. Both use
`WHATSAPP_TEMPLATE_LANGUAGE`. Without these templates the app still uses
ordinary WhatsApp messages, which work only while the 24-hour service window is
open. Meta must approve these templates before they can be sent.

## Notes & limitations (MVP)

- PDF extraction works best with **text-based** PDFs. Scanned/image PDFs
  fall back to OCR (`eng.traineddata`, see `services/ocr.js`), which is slower
  and less accurate — prefer a text PDF where possible.
- The WhatsApp **first message** to a new student requires an approved template
  (Meta policy). After the student replies, the 24h session window allows the
  free-flowing question/answer exchange the system relies on.
- AI theory marking errors never block the exam: the answer is recorded,
  flagged for review, and the exam continues.
